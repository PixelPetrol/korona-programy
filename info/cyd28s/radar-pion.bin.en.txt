A version for the CYD 2.8" with an ST7789 panel (the board with two USB sockets) - built, NOT TESTED ON HARDWARE. On this revision the colours are decided by TWO switches, not one: the ST7789 driver in the library sends INVON unconditionally at start, and the radar itself sets the inversion its own way after initialisation. The profile sets both so that the result comes out in line with the canonical setting of this board. Should the image still come out as a negative - it can be switched DIRECTLY IN THE RADAR MENU (settings -> inversion), without rebuilding anything. The SkyCYD interface is in Polish only. K-OS COMPATIBILITY: this program was written EARLIER than K-OS and is deliberately not aligned with all of its features. It does not use the SD card at all, so it does NOT read the shared settings from the card (theme, language) nor the shared touch calibration - it has its own theme, its own language (Polish) and its own touch calibration, set in its own WiFi portal. 4.4.2: THE PORTAL ON SOMEONE ELSE BOARD - from an external tester who ran 4.4.1 on his own 2432S028R. TESTED ON HARDWARE: the network list in the portal was always empty, because on a board that is not configured yet the radio went into AP-ONLY mode while scanning needs a client interface (and the scanNetworks result was ignored on top of that, so a failed scan looked like having no neighbours); the mode is now pinned to AP+STA and the tester sees 13 networks instead of none. FIXED BUT NOT TESTED ON HARDWARE: the access point handed out no addresses even though softAP and softAPConfig both returned OK - softAP() now runs BEFORE softAPConfig(), we ask the DHCP server for its state and start it by hand when it is not running, and the lease now carries a DNS server; the AP name came out as SkyCYD-0000 because the MAC was read before the radio mode was up; entering SSID and password by hand now answers at once instead of waiting 18 s for the AP to hop channel. ALSO NOT TESTED: the 2.8 inch touch calibration moved from the firmware into the portal (Network -> Touch calibration), because until now the four ADC range numbers were baked into the image and on someone else panel there was no way to change them; the screen in the board menu now shows the raw ADC reading live.
